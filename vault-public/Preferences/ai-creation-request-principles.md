# AI創作依頼の原則（要素を削るほど良い）

AI に創作（デザイン・アイデア出し・作品制作）を依頼するときは、**方向を足すのではなく、ありきたりを引く**。

## ルール
1. 主題の縛りは最小個数まで削る（要件・参考作品・過去の好みの注入は原則しない）。
2. 残してよい制約は2種類のみ:
   - **品質バー**: 目の肥えた受け手を想定させる・定番/既出比喩の禁止。
   - **回避リスト**: 既出案との重複防止のネガティブ制約。
3. 並列発散させる場合は、ラウンド内の被り防止の一言だけ足す。

**Why:** 発散ラウンドの実測比較で、要件を注入した世代より縛りを削った世代の方が発想が明確に跳んだ（経緯・実測＝[[Decisions/2026-07-12-ai-creation-minimal-constraints]]）。
**How to apply:** 創作依頼プロンプトを書く前に「この注入は削れないか」を問う。方向づけたくなったら、品質バーか回避リストの形に変換できないか先に検討する。

## 成果物の公開区分（既定＝内部利用・2026-07-19 本人決定）
1. **「作って」という依頼の既定は内部利用（非公開）**。明示がない限り、成果物は Vault・ローカル・私的閲覧の範囲で完結するものとして作る。素材（画像等）は**私的使用の範囲で調達してよい**（そのぶん出典の幅を広く取れる）。私的使用前提の素材を含むファイルには、その旨（公開不可）をファイル内に明記する。
2. **公開は本人が「これは公開」と明示したときのみ**。置き場も原則 public GitHub 等に切り替わる。このときは [[Preferences/absolute-rules]] 1（ライセンス基準）をフル適用し、私的使用前提の素材は使わない・差し替える。
3. 内部利用として作った物を後から公開に切り替える場合は、含まれる素材の権利を**再点検してから**公開経路に乗せる。

**Why:** 内部利用と公開物では使える素材・かけるべき慎重さが大きく違う。既定を内部利用に置くことで、日常の制作は速く・公開時だけ厳格に、と切り分けられる。
**How to apply:** 制作依頼を受けたらまず「公開の明示があるか」を確認し、なければ内部利用として進める。公開の話が出た時点で素材の権利チェックをやり直す。
