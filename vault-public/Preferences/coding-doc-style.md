# 設計・記述の運用ルール（共有ライブラリ分離／資料の新旧同期）

夜間バッチの昇格提案 frag-2c396e816aea を本人承認で昇格（2026-07-20。初出＝Fragments 2026-07-16 の本人指摘2件）。

## 1. 共有ライブラリは実行エントリポイントに同居させない
複数の呼び出し元から使われるコードは、CLI スクリプト等の実行エントリポイントに同居させず、独立ファイルに分離して「共有資材として参照される」構造にする。

**Why:** CLI と lib が同居すると責務が曖昧になり保守性が下がる（実例＝vault_inventory の CLI/lib 同居指摘。一般則化＝[[Decisions/2026-07-16-simplification-item-cleanups]] 項目10）。

**How to apply:** 新規実装・委任時の設計段階でエントリポイントと共有部を分ける。レビューで同居を見つけたら分離を指摘する。

## 2. 資料の改訂は「本文＋差分」をセットで更新する
設計書・要件書など、本文と差分（変更点まとめ）の両方を持つ資料を改訂するときは、必ず両方を同期して更新する。

**Why:** 片方だけ更新すると新旧の記述が食い違ったまま残り、後から参照した側が誤った情報を掴む（実例＝設計書 v1/v2 の不整合指摘）。

**How to apply:** 改訂タスクの完了条件に「本文と差分の両方を更新した」を含める。ワーカー委任時はプロンプトに明記する。
