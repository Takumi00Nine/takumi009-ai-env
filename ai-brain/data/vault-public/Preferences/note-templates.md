# ノート本文の軽い型カタログ（推奨・強制しない）

AI がノートを書くときの推奨スケルトン集。**テンプレ穴埋めを義務にしない**（即時 capture の速度が最優先）。一般の解説・調査・手順など、型に合わない知識は自由形式でよい。**教訓の記録と新しい本人の判断は、下の必須項目を持つ**（[[Decisions/2026-11-02-external-brain-three-stage-ladder]]・[[Decisions/2026-11-02-use-decisions-recall-and-rule-change]]）。共通原則＝結論を冒頭に／1ノート約8,000字以内／aliases は任意（既存は残す）／メタデータ（frontmatter）は既存規約どおり。

**Knowledge のノート名・単位は「後で追記・統合される前提」で付ける（2026-07-21 本人指示）**: 個別事例名で切らず、将来の同類が collect できるカタログ名にする（実例: `bgmer-free-bgm`（個別サイト名）→ `free-bgm-sites`（フリーBGMサイト一覧）に改名。BGMer はその1エントリ）。本文もカタログ構造（サイト/項目ごとの節＋「新しく使ったら追記する」運用文）にしておく。
**Why:** 個別名のノートは同類が増えるたびに分裂し、knowledge-merge の統合コストになる。最初から器を大きく作れば追記だけで済む。
**How to apply:** Knowledge 新設時に「これの同類は今後増えるか?」を自問→増えるなら一覧/カタログ名＋カタログ構造で作る。単発性が確実なもの（特定バグの罠集等）は従来どおり個別名でよい。

## 型1: 罠集（技術的な落とし穴の記録）

```
# <対象> の罠集
## 罠N: <一言で現象>
- 現象 → 確定条件（実測でどう再現するか） → 対策 → （あれば）出典
```
実例: 実測値・境界条件・「見かけの症状と真因の違い」を必ず残す。

起きたことから「次はこうする／しない」が分かる教訓には、次のブロックを教訓ごとに置く。1ノートに複数置ける。一般の解説・調査・手順には足さない（[[Decisions/2026-11-02-external-brain-three-stage-ladder]]）。

```markdown
## 教訓: <教訓ID>
- 教訓1行: <前提知識なしで行動に移せる「する／しない」の1文>
- 効く場面:
  - <本人やリーダーが実際に口にする発言・作業>
- 起きたこと: <最初の発生の短い経緯>
- 発生記録:
  - YYYY-MM-DD [[Fragments/YYYY-MM/YYYY-MM-DD#出典の節]]
```

`教訓ID` はノート内で一意な短い名前。文面や見出しの順が変わっても変えない。発生記録は最初の発生を含め、発生順に日付と出典（断片・検証の指摘・三点セット）を1件1行で書く。同じ出来事に出典が複数あっても1行にまとめる。同日の別の発生は別行。日付・出典は発生記録だけに置く。

状態は教訓のままなら無印。規則化したら `- 状態: 規則化済み → [[Preferences/ノート#節]]`、本人不在で提案を待つ間は `- 状態: 規則化を提案中`、本人が見送ったら `- 状態: 規則化見送り（YYYY-MM-DD）` を付ける。規則の保存前に規則化済みにしない。規則側からも教訓へリンクする。


## 型2: 判断記録（Decisions/）

```
# <何を決めたか>
- 判断1行: <本人が何をどう判断したかを一読で分かる1文>
- 効く場面:
  - <その判断を出すべき発言・作業>
- 判断の日付: YYYY-MM-DD

**決定（YYYY-MM-DD・決定者）:** 一文で。
## 経緯 / ## 選択肢と判定（A vs B＋根拠） / ## 適用（波及チェック: grep語と修正ファイル）
```

判断の日付は本人が判断した日。更新日や埋め戻し日で代用しない。理由・選んだ案・経緯は既存の本文を残す（[[Decisions/2026-11-02-use-decisions-recall-and-rule-change]]）。

## 型3: 手順書（繰り返し実行するオペレーション）

```
# <手順名>（正本）
## 前提チェックリスト（スキップ禁止事項） / ## 手順A: 通常系（番号付き） / ## 手順B: 異常時 / ## 制約（変更しないこと）
```

## 型4: 台帳（所有物・契約などの事実一覧）

```
## <カテゴリ>（確認日）
- **品名/契約名**（型番・ASIN・月額など機械照合できる識別子・一言の用途）
```
1項目1行・確認日を残す・変更があれば行を書き換え（履歴は git）。

## 型5: 調査結果（Web・実測のリサーチ）

```
# <問い>
結論（1〜3行・確度と調査日） → 根拠（実測値・比較表） → 出典（一次情報URL） → （必要なら）review_by
```

> 迷ったら型を探すより先に書く。型はあとから整えられるが、書き漏らした事実は戻らない。
