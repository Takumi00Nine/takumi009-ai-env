# 絶対厳守ルール一覧
リーダー・ワーカーとも例外なく守る、非交渉のルール。**ワーカーは新規起動・継続とも、このノートを全文読む**。必読指示はラッパーと職種定義が付ける。詳細は各リンク先。
1. **ライセンス上パブリック公開不可のアセットは公開しない** — 判断基準は**ライセンス**。購入・入手した3Dモデル（VRM/素体含む）・素材・フォント等、再配布・公開が許されないものを外部取得可能な場所（公開リポジトリ/GitHub Pages 出力/公開 Actions 成果物等）に置かない。公開可ライセンスは公開してよい。派生物はライセンスが許す範囲で public 可（現行アバター＝VN3＝本体再配布禁止・2D派生物は二次創作範囲で可＝[[Preferences/vrm-license-policy]]）。不明・迷う場合は公開せず本人に確認。
2. **リポジトリの public 化はユーザーが自分で実行する** — AIは `gh repo edit --visibility public` 等の public 化操作を代行しない。AIはprivate作成〜pushまで。（[[Preferences/git-workflow]]）
3. **認証情報・シークレットを露出しない** — トークン・鍵・パスワード・`.env` などを、出力・コミット・ログに含めない。
4. **必ず裏取りしてから進める** — 実装・回答・設定変更の前に毎回、一次情報で確認してから着手（推測で進めない）。外の変わりうる情報（製品・料金・仕様・ニュース等）は Web で、内部の決まり・実装・手元の設定は正本を読むか実測で確かめる。軽い確認はリーダーが直接、重い・多方面の調査はワーカー（researcher）へ。（[[Preferences/web-verify-before-acting]]）
5. **着手前に公開リポジトリで類似OSS・先行実装を検索する** — 要件定義が固まった段階で GitHub 等を検索し、既存ツールで代替できるなら「作らない」判断を優先。担当はワーカー（researcher）。調査先＝[[Knowledge/oss-prior-art-search]]。
6. **すべての成果物は、目的を満たす最も単純な形にし、読み手が一読で分かるように書く** — 職種・工程・成果物の種類を問わず全部に当てはめる。判定は2軸＝**単純**＝部品・条件・例外・分岐は目的に必要な数だけ。迷ったら削る側。／**明快**＝前提知識のない読み手（本人・次のセッション・別の職種）が一読で理解できる。用語・構成は既存に揃え、説明が要る形を選ばない。「動く」「指摘が消える」は複雑さを足す理由にならない。⚠️ 短くする≠境界を消す＝単純化は境界（責務・対象／対象外・例外）を保ったまま部品を減らすこと。適用例＝[[Preferences/core-worker]] §3・[[Preferences/core-workflow]] §2。（[[Decisions/2026-09-21-simplicity-principle-layer0]]）
7. **後から変えたくなる値をハードコードしない** — 設計・実装のどちらでも、閾値・周期・回数・上限・パス・名前・モデル名など「後で変えたくなりうる値」は、コードに埋めず設定ファイル・オプション・環境変数のいずれかで外から変えられる形にし、既定値は1か所に置く。判定＝「この値を変えるのにコードを直す必要があるか」＝要るなら違反。設定項目は目的に必要な数だけ（⑥）＝変える見込みの無い定数は名前付きで1か所に置くだけでよい。（[[Decisions/2026-09-22-no-hardcoded-tunables]]）
> 追加・変更はメイン機のリーダーのみが行う。実行前にローカルプロファイルの `machine_role` が `configured value=main` であることを確認する（[[Preferences/core-workflow]] §5）。毎回読ませる構成上、項目を増やせば各ワーカーへも自動反映される。
