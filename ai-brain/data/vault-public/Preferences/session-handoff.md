# セッションは区切らず、要約して同じ画面で続ける

リーダーは自分から新しいセッションを作らない。会話が長くなっても、休憩をはさんでも区切らず、ツール内蔵の要約で同じ画面のまま続ける。続きの正本は案件ノート（Projects）と、そこから参照する案件のファイル。理由＝[[Decisions/2026-10-31-no-session-split-compact-in-place]]。

## 要約
- 要約を始める長さ＝両ツールとも 300k トークン。値は ai-env の設定のひな形の1か所に置き、両ツールの設定へ生成する（変えるのはそこだけ）。強制的に区切る上限は置かない。放置時の自動要約はツールの既定のまま使う。
- 要約のあとは、起動時の案内が入り直していることを確かめる。必読本文が全文入っていなければ（案内だけ・一部欠落・省略表示）、欠けた本文を読み直してから作業を続ける（[[Preferences/core-conduct]] §1）。要約の中の「読んだ」は全文の代わりにしない。
- 要約の直後に大きな出力を読み直すことを繰り返さない＝開始目安に対して大きすぎる読み込みが続くと、要約しても即満杯になり作業が止まる。大物はワーカーに読ませて結論だけ受ける。止まったら原因の読み込みをやめ、案件ノートと実ファイルから続ける（閾値を黙って上げない・別画面を起動しない）。

## 先に書く（案件ノート）
- **書く時機**＝①工程の節目 ②本人の意図・決定・留意事項がまだ書かれていない状態で、大きなファイルの読み込み・長い処理・まとまった結果の受け取りへ進む前 ③要約が近いと分かったとき（警告が出たとき）。警告は来ないこともある＝①②を主な手段にする。
- **書く中身**＝[[Preferences/project-tasks-format]] の本文5節にそのまま入れる（新しい節・再開専用の文書は作らない）。進捗と次の一手＝Tasks の記号・`next`・「今どこ・次に何を」／本人の意図・確定した前提・留意事項＝「守ること」／未決の論点と傾き・捨てた案と理由＝工程の検討経緯に書き、「今どこ・次に何を」からリンク。本人の発言とリーダー案を分け、未決を決定済みにしない。
- **残作業の消化**＝「後で／締めで」と言った小作業は、節目ごとにその場で終える（[[Decisions/2026-09-21-drain-deferred-tasks-before-handoff]] の考え方を節目に当てる）。
- Claude Code のとき：長さの警告（`context-size-warn.sh`）は要約の開始目安から再警告の幅（既定 50k）を引いた長さ（既定 250k）で出る。文面は「案件ノートの未記録分を今書き、同じ画面で続ける」。

## 本人が新しいセッションを始めたとき
- 新しいセッションを始めるのは本人だけ（ツールを替える・画面を閉じた・ツールが落ちた）。始まったリーダーは、案件ノートを読み、旧作業（前のリーダー・その子の処理）が止まっていることと成果物の実態をファイル・実行状態から確かめてから続ける。動いている・確かめられない（権限で見えない等）なら作業を始めず本人に聞く。実行中だった処理の完了を推測しない。会話の履歴・再開用の識別子に頼らない。
- 同じ案件を2人で同時に進めない＝前のリーダーや子の処理が動いている間は始めない。

## やらないこと
- 再開メモを書かない（置き場ごと廃止）。新しい画面を開いて続きを渡さない（起動スクリプトは廃止）。区切るかを本人に確認しない（区切らないのが既定）。
- 新しいセッションへの続行指示に SendMessage（cross-session）を使わない＝[[Preferences/cross-session-messaging]]。

> 旧方式（切れ目の3条件・再開メモ・リーダーによる新セッション起動・強制上限 800k）は 2026-10-31 撤回。経緯＝[[Decisions/2026-10-03-strict-session-split-criteria]]・[[Decisions/2026-09-16-leader-spawns-next-session]]。
