# Codex を実装ワーカーとして直接起動する手順（`codex exec` 背景実行）

**Codex 子の起動は `~/Workspace/Tools/takumi009-ai-env/team/connect/codex/codex-exec.sh` 経由のみ**（MCP 廃止＝[[Decisions/2026-09-06-codex-mcp-retire]]）。呼び出し経路は規則として守る。一次レビューの割り当ては [[Preferences/codex-review-protocol]]。

用途＝リーダーが Codex を implementer 等の職種ワーカーとして起動する手順。担当・起動条件は [[Preferences/coding-delegation]] に従う。

親の種類による非同期起動・完了の受け取りは [[Preferences/worker-role-prompts]]「起動形態の既定」を参照する。

本ノートは委任のたびに Codex に読ませるため**最小サイズを維持**する（起動手順のみ。背景・経緯・他経路の説明は書かない）。レビューの割り当ては正本＝[[Preferences/codex-review-protocol]]。

実測環境＝codex-cli 0.144.6・2026-09-03・メイン機。

> **消す作業は任せない（2026-11-01 実測）**＝Codex の実行環境からはゴミ箱（`/usr/bin/trash`）が権限エラー（NSCocoaErrorDomain 513）になる。ワーカーには「消す一覧（絶対パス）」を作らせ、ゴミ箱への移動はリーダーが行う。

## 起動の型
`--role` は初回・継続とも必須。以下のラッパー呼び出しを、上記の非同期起動手順で実行する。

```bash
~/Workspace/Tools/takumi009-ai-env/team/connect/codex/codex-exec.sh \
  --role <職種名> \
  --sandbox danger-full-access \
  --cwd /abs/path/to/target \
  --prompt-file /abs/path/request.md \
  --out /abs/path/report.md \
  --model <選んだモデル> --effort <選んだeffort> \
  2> /abs/path/report.wrapper.log
```

- 完了後は `--out` を読む。events の全文は読まない。
- `--cwd` は担当範囲の絶対パスに最小化し、ホーム全体は渡さない。出力先の親ディレクトリを用意する。
- 初回・`--resume <thread_id>` の継続とも `--role <職種名>` を指定する。継続は同じ職種、改役は新規起動にする。thread_id と終了値はラッパーの出力で確認する。
- ラッパーは新規起動・継続とも、`~/Data/obsidian/Preferences/absolute-rules.md`・`core-worker.md`・`worker-role-<職種名>.md` を全文読む指示を自動で付ける。依頼文へ absolute-rules の参照を手で書く必要はない。
- 職種の本文・権限・出力形式は各 [[Preferences/worker-role-prompts|職種ノート]] を参照する。`--developer-instructions` へ職種本文を切り出して渡す運用は終了する。このオプションは個別案件の入力用に残す。
- 依頼文には承認済み設計・担当ファイル範囲・受入条件・Vault 書込禁止を示す。新しいファイルを追加するときは、その repo の登録表（ai-env なら `core/data/ledger.tsv`）の更新も担当範囲に含める。報告の固有指定があれば添える。
- 大きい作業は工程や成果物の区切りで分ける。継続するときはリーダーが `--resume` を明示する。
- `--sandbox` は必須なので、`--sandbox danger-full-access` を明示する。既定方針は `danger-full-access`（[[Decisions/2026-10-10-codex-sandbox-full-access]]）。担当範囲は依頼文で指定する。
- 画像は `--image <path>`（繰り返し可・`--resume` 併用可）で渡す。Web裏取りが要るときは `--search` を付ける。
- モデル・effort は配役表から選んだ候補を `--model`・`--effort` で渡す。
- 依頼文の stdin 送信、開発指示の文字列符号化、ログ保存はラッパーが行う。

## プロジェクトリーダー（親）として起動・再開する（三段の体制）
ワーカーとして呼ばれた Codex は本節を読まなくてよい。マックリーダーが既存ラッパーで親を起動・再開する経路で、親とワーカーの規範供給を分ける（親に core-workflow の親向け必読を参照させ、子の Vault 禁止・専門職の職務を当てない）。親向けの起動の区別はラッパー側の実装後に使う（[[Decisions/2026-11-03-three-tier-team-stage1]]）。
- 親は案件一式（フォルダ・Projects ノート・宣言・画面）の完成後に起動する。初回は作業一覧・見積り・停止点・体制の報告まで。本人承認後は同じ会話で作業を始める。
- 外側の親は所要時間にかかわらず切り離して実行し、同じ会話を明示して再開する。初回の候補選択はマックリーダー。再開では保存したモデル指定と案件の前提を黙って変えない（利用枠の再確認は選び直しと分ける）。会話と案件・実行中プロセス・実行結果を対応づけ、終了値と最終報告を一組で回収する。
- 稼働中の子の終了待ちは親が内蔵の通知待ちで行い、往復ごとに外側へ戻らない。
- 本人確認・利用枠等による続行不能・動かせる仕事のない報告区切りでは、子の停止・一旦終了を確かめ、要約と判断待ちを保存して報告を終える。通知は [[Preferences/cmux-notifications]] に従う。
- 本人に見せたい・確認してほしい資料は、親も子も cmux に表示しない（show-review.sh を呼ばない）。資料のパスと見てほしい点を報告に入れて返し、マックリーダーが自分の画面の隣に表示する（[[Decisions/2026-11-03-show-via-mac-leader]]）。
- 非0終了、またはプロセスが無く終了値も残っていない場合は状態未確認。マックリーダーが旧実行が動いていないことと利用枠を確かめ、復旧確認だけを依頼して同じ親を再開する（止まるたびに一度だけ・新しい制作は始めさせない）。混雑など一時障害の立ち上げ直しは本人へ確認せず次の報告に1行（[[Decisions/2026-11-06-leader-restart-per-failure]]）。親は全員の停止位置・差分・書きかけを確かめて記録を直す。復旧できなければマックリーダーへ返し、別の親を同時に起動しない。
- **全案件の状態確認**＝既存の案件宣言・案件ノートの「正本の所在」と、各案件の親の状態記録を読む共通の入口を使う。一回の呼び出しで一覧を得られ、親が停止中でもモデルを呼ばずに読める。オプションで単発表示と継続更新を選べ、間隔も指定できる（案件別 view --watch と同じ読み直し方式）。常駐収集・モデルへの問い合わせ・親子の起動・呼び戻し・復旧はしない。
  - 親の生存・終了は単発でも継続の各回でも、実行中プロセスとラッパーの終了値・報告で観測する。子の状態・相談中の組・停止確認・許可は親の明示記録と担当表から取り、親の生ログで補わない。未受領・受領後・結論済み・依存先待ちの相談を分け、全履歴を現在の組として並べない。
  - 子の状態の反映は親が記録した時点まで。表示時点・親の観測時点・子の記録時点を分け、表示の更新だけで子の状態を新しく確認したと扱わない。親の異常終了・生存不明が分かれば未確認へ更新し、そこから子の停止・完了を推定しない。
  - 案件ごとの記録時点と未確認を出し、一案件の読取失敗で他案件の結果を捨てない。親未起動と確認できる準備中は未起動・0人、あるはずの記録の欠落は未確認。親を立てていない従来経路の案件はその区別を示す。異常の復旧は上の親の手順へ返し、一覧の読み取りに混ぜない（[[Decisions/2026-11-03-three-tier-team-stage4]]）。

## 案件内の子（三段の体制・段階2）
外側（マックリーダー→親）は上の親の節のまま。案件内の子は親の Codex 内蔵経路で動かし、外側ラッパーから一人ずつ複製しない。MCP は使わない（[[Decisions/2026-11-03-three-tier-team-stage2]]）。
- 親は担当表に残した同じ子の宛先で、内蔵の再開により呼び戻す。終了した相手へ連絡を送るだけで動いたとは扱わない。親を再開した直後に子が一覧に見えなくても消失とせず、記録した宛先への再開結果で判断する。
- 内蔵機能の実行状態と仕事の状態（引き継ぎ済み・相談待ち・停止中など）を分けて明示記録する。正常終了だけで品質承認や再開許可にしない。
- 内蔵の結果と、子が指定先へ保存した成果を突き合わせる。外側の親のログや終了値から子の完了・停止を推定しない。
